| Claim | Status |
|-------|--------|

## Discrepancies

1. **Documentation mentions `unicode_tools.detect_confusables()` but actual function is in `unicode_tools.py`** (minor - both are correct references)

2. **Comment in confusables.py is misleading** (line 12): "Names are derived at runtime via unicodedata.name()" - The CONFUSABLES table contains codepoint strings like `"U+0430"`, not actual characters with names. Names are derived at lookup time in `detect_confusables()`, not when the table is defined.

3. **Generator script has header-skipping bug**: In `parse_confusables()` (line 89), the condition `if stripped.startswith("0") or stripped.startswith("#")` would skip lines starting with "0" that are valid data lines (e.g., code point `0x0...`). However, the subsequent `data_started` flag mitigates this - it only skips header lines until the first data line.

4. **Documentation shows example structure incorrectly**: The doc shows `"U+0430": "U+0061"` but actual entries use space-separated multi-codepoint substitutions like `"U+0430": "U+0061"`.

## Bugs Found

### Medium: `generate_confusables.py` header detection could skip valid data
**Location**: `scripts/generate_confusables.py:89`
```python
if stripped.startswith("0") or stripped.startswith("#"):
    continue
```
Lines starting with "0" (hex code points like `0x0C80` - `0x0CFF` for Tagalog) would be incorrectly skipped as headers. The `data_started` flag provides a partial workaround but is not robust.

### Low: `detect_confusables` lacks case where character maps to itself
**Location**: `nl_calc/exact/unicode_tools.py:175`
```python
confusable_with = "".join(chr(int(cp[2:], 16)) for cp in sub_str.split())
```
If a character maps to itself (e.g., `U+0061` → `U+0061`), it would be returned as a confusable but `confusable_with == char`. The test `test_detect_confusables_none` accounts for this, but the function could filter these out entirely for clarity.

### Low: No caching on `detect_confusables`
The function parses substitution codepoints and looks up names each time. For repeated calls with same input, memoization could help.

## Improvements

| Priority | Item | Rationale |

## Architecture Assessment

The module architecture is sound:
- Clean separation: data (`confusables.py`) vs. logic (`unicode_tools.py`)
- Generator script allows regeneration from Unicode source
- The CONFUSABLES table is a straightforward codepoint-to-codepoint mapping
- `detect_confusables()` properly parses the space-separated substitution codepoints

The confusables.py file is large (~180KB, 6581 lines) but appropriate for the comprehensive Unicode confusables table. The single-table approach is simple and efficient for lookups.

## Summary

The confusables module implementation is fundamentally correct and well-structured. The main issue is a potential bug in the generator's header-skipping logic that could skip valid data lines starting with hex digits. The documentation accurately describes the purpose and usage of the module.
